# Working on Awesome LEGO with Claude

Public directory of the brick world: data in `data/*.toml`, README and a bilingual website built by `scripts/build.py` from `site-src/`, published by GitHub Pages. Everything in this repository is in English except the French texts of the data and the website.

- **State, decisions and open items** are the maintainer's working notes in `dev/`, in French (an exception to the English rule, limited to `dev/`: the `passation` tooling reads French column names and statuses): `dev/contexte.md` (state, decisions, pitfalls, sources), `dev/registre.md` (everything left to do, one line per item), `dev/registre-clos.md`, `dev/lots/` (one brief per batch of work). Read the first two before any work; update them at each delivery. `dev/outils/passation.sh` (configured by `passation.conf`) checks them; a squash merge keeps only the pull request title, so the review blocks of `passation` (`Relecture:`, `Constats:`, `Registre:`, `Savoir:`) go in the pull request body.
- **How the repository runs**: `MAINTENANCE.md` (workflows, schedules, the maintainer's tasks); rules of the data: `data/SCHEMA.md`; selection rule: `contributing.md` and `site-src/about.json`.
- **A pull request never changes `VERSION`, the sections of `CHANGELOG.md`, `README.md`, `full-list.md`, the category list of the issue form or the README images**: it adds `changes/<name>.md` (types: `MAINTENANCE.md`, section Versions; format: `scripts/changes.py`), and right after the merge the workflow **Version** writes them on `main` as the next version (`X.Y`, or `X.Y.Z` for a patch), which **Pages** publishes; Check refuses the rest, and a change of `data/`, `site-src/` or the scripts that make the pages without a fragment (type `none` when no page shows it). Each merge is a version: a batch of work is one pull request, its preview (merged with `main`) shows what goes out and its banner the number. Branch from `main`, never from an unmerged branch; merges are squashed by the maintainer, and the title of the pull request becomes the commit on `main`.
- **Variants for the maintainer to choose from**: one commit each, marked with a trailer `Preview-compare: <commit> <what to look at>` (in that commit or a later one, in the last paragraph of the message with `Co-Authored-By`): the preview lists them in bold and puts them side by side (`MAINTENANCE.md`, Preview).
- **A fragment says what changes in two sentences** (about 250 characters, 550 at most: Check fails beyond); the details go to the pull request.
- **Before pushing**: `python3 scripts/changes.py check --base origin/main`, `python3 scripts/build.py --check`, `python3 -m unittest discover -s tests`, `python3 scripts/build.py --site-only && python3 scripts/hygiene.py` (ruff and vulture from `tests/requirements-check.txt`), `python3 scripts/check_site.py` with and without `--dejavu` when the website changes (the image of the README is taken by **Version**). Workflows: `actionlint` and `zizmor --offline`.
- A section renamed is renamed in the page title and description too; a value is written once, elsewhere a reference to it.
- **Settled by the maintainer** (not to be raised again without a new reason): the faint grey `--faint` stays at 5.6:1; no installable app (PWA); no visit statistics; Renovate rather than Dependabot for updates; no required review and no stricter ruleset on a one-maintainer repository; contact through GitHub only; a stale README image warns, never fails.
